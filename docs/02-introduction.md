## 1.1 Attention Getter：研究設備閒置是公開且長期的問題

研究設備低使用率不是單一學校的問題。監察院 2013 年針對國科會貴重儀器補助的調查報告指出，2007–2011 年國科會每年平均補助約 2.2 億元購置 13 台貴重儀器；但 2011 年查核發現 8 所國立大學使用率偏低，部分核心設施全年服務次數不到 100 次，且補助計畫結束後缺乏退場與營運機制 [2]。

十多年後，同樣的問題仍是政策焦點。韓國科技部與教育部於 2026 年 5 月提出研究基礎設施開放政策：全國設備系統（ZEUS）登錄 93,480 件研究設備，其中大學持有 22,335 件（約 24%），並舉例一台價值 18 億韓元的半導體分析儀器因缺乏維護預算而閒置數年 [1]。

另一方面，採購流程正被 Agentic AI 重塑。依 Procurement Magazine 2026 年彙整，Gartner 預測 2028 年 90% 的 B2B 採購將經由 AI Agent 中介；但 The Hackett Group 研究也指出，2024 年有 49% 採購團隊試行 AI，僅 4% 達到大規模部署 [3]。

**小結**：設備閒置的代價是公帑，採購 AI 的技術已經出現，但兩者之間缺少一個能在學校法規框架下落地的工具。

## 1.2 Background：應用領域、使用者與技術背景

**領域規則。** 在台灣的大專校院，單價新台幣 1 萬元以上且使用年限 2 年以上的設備屬於「財產」，未達者為「物品」[13][14]。財產需列帳、指定保管人，並依《財物標準分類》所定最低使用年限辦理報廢 [14]。採購端受政府採購法與校內請購規範約束，例如 15 萬元以下為小額採購、150 萬元以上達公告金額，並可透過共同供應契約下單 [15]。

**使用者。** 實驗室中有三類使用者：實驗室成員（借用設備、提出請購）、財產管理人或助理（登帳、盤點、報廢）、指導教授 PI（核准採購與報廢）。三者的權限與責任不同，系統必須區分。

**技術背景。** LLM Agent 透過 ReAct 式「推理—行動」交錯 [12] 與 Tool Calling，已能操作資料庫與網頁；Agentic RAG 進一步讓 Agent 自主決定何時檢索、檢索什麼 [8]。

## 1.3 Problem：真正要解決的問題

| # | 問題 | 典型情境 | 後果 |
|---|---|---|---|
| P1 | 資訊斷裂 | 「實驗室現在有哪些可借的 GPU 主機？」沒有人答得出來 | 財產清冊、借用紀錄、採購文件分散在 Excel、紙本與學校系統，帳實不符 |
| P2 | 價值不透明 | 「這台三年前買的示波器現在還值多少？要修還是要換？」 | 帳面價值只反映法定年限，維修或汰換缺乏依據 |
| P3 | 先買再說 | 新生入學就直接請購新電腦 | 缺少先查庫存與閒置財產的強制步驟，造成重複購置 |
| P4 | 法規門檻高 | 學生不知道 16 萬元的設備要走不同流程 | 金額門檻、報價份數、最低使用年限與報廢分級不熟，文件常被退件 |

## 1.4 Existing Limitations：現有方法的不足

| 既有方法 | 能做到 | 做不到 | 對應問題 |
|---|---|---|---|
| 校內財產系統 | 登帳、盤點 | 自然語言查詢、殘值估算、採購決策支援 | P1、P2 |
| 商用採購 AI（SAP、Zycus 等） | 企業採購流程自動化 | 未內建台灣政府採購法與公立學校財物規範；對單一實驗室過於昂貴 | P3、P4 |
| 通用 LLM 聊天機器人 | 自然語言互動 | 直接回答數值與法規會幻覺；端到端求解成本較高 [4]；多步驟工具任務不穩定 [6] | P2、P4 |
| 網購比價 Agent | 搜尋商品 | 多屬性、篩選與排序成功率低 [5]；商品比對對 prompt 敏感 [7] | P3 |
| 殘值預估研究 | 重型機具、汽車、手機的殘值迴歸 [10][11] | 未處理「交易資料稀少、規格差異大」的實驗室儀器 | P2 |

## 1.5 Innovation：本專題的不同之處

| 創新 | 做法 | 解決的限制 |
|---|---|---|
| C1 LLM 只協調、不判斷 | 借鏡 [4] 的混合式架構：金額門檻、年限、折舊一律交給確定性程式與規則引擎；LLM 負責追問、拆解與解釋 | 通用 LLM 的幻覺與不穩定 |
| C2 管理與採購打通 | 採購流程第一步強制查詢自有庫存與閒置財產，把「先共享、再採購」寫進演算法 | 先買再說、重複購置 |
| C3 雙軌殘值 | 同時輸出法定帳面價值與市場估值區間，資料不足時標示低信心 | 價值不透明、殘值研究未涵蓋實驗儀器 |
| C4 法規可追溯 | 每項建議附上法規條文或資料來源，寫入稽核紀錄；會改變帳務的動作需人工核准 | 法規門檻高、責任歸屬不清 |

## 1.6 Contributions：預期貢獻

1. **系統架構**：提出一個可實作的實驗室財產管理與採購 Agent 架構（8 個模組、2 個子 Agent、8 項工具），並以 OpenSpec 撰寫可驗證的需求規格。
2. **法規知識庫**：建立台灣大專校院財產與採購法規的結構化知識庫與規則檔，可供其他實驗室依校規調整後重用。
3. **殘值方法**：提出融合法定折舊與二手市場資料的雙軌殘值預估方法，以區間呈現不確定度。
4. **評估基準**：建立約 50 題實驗室情境測試集與評估指標，納入法規違規率與 pass^k 穩定度。
5. **開源交付**：公開 GitHub 專案、README.md、DESIGN.md 與 OpenSpec 規格，使後續開發者可以接手。

## 1.7 Research Questions

- **RQ1**：將數值與合規判定從 LLM 移到規則引擎後，法規違規率與 pass^k 穩定度相較單一 LLM 與純 RAG 有何差異？（對應 C1、C4）
- **RQ2**：強制「先查庫存」的採購流程能找出多少可借用或移撥的設備？（對應 C2）
- **RQ3**：雙軌殘值的市場估值區間與二手市場價格的誤差為何？資料不足時低信心標示是否可靠？（對應 C3）
