## 2.1 AI Technology

### 2.1.1 LLM Agent 與工具調用

- **研究發現**：ReAct 讓語言模型在「思考」與「呼叫工具」之間交錯，是目前多數 Agent 框架的基礎 [12]。τ-bench 專門評估 Agent 在「工具—Agent—使用者」三方互動下是否遵守領域規則：GPT-4o 在零售情境的成功率約 61%，但同一任務重跑 8 次都成功的比例（pass^8）低於 25% [6]。
- **限制**：平均成功率掩蓋了不穩定性；只涵蓋零售與航空兩個領域。
- **設計啟示**：財產與採購屬於「錯一次就有後果」的場景，本專題以 pass^k 量測穩定度，並以狀態機限制 Agent 的行動範圍。

### 2.1.2 混合式架構：LLM + 確定性求解器

- **研究發現**：Duan 等人在中小企業庫存管理中比較「LLM 端到端求解」與「LLM 擷取參數 + 呼叫最佳化演算法」，後者總成本降低 32.1%；即使給 GPT-4o 完整正確資訊，端到端表現也未改善，顯示瓶頸在計算推理而非資訊不足 [4]。
- **限制**：以模擬經理人評估，非真實使用者。
- **設計啟示**：殘值計算與門檻判定交給程式與規則引擎，LLM 只負責參數擷取與解釋（C1）。

### 2.1.3 Agentic RAG 與領域知識庫

- **研究發現**：Agentic RAG 綜述將「由 Agent 決定檢索策略、反覆查證」整理為新的設計模式 [8]。Liu 等人以 3,500 篇以上材料論文建立輕結構化文字資料庫，結合向量檢索、BM25 與數值過濾，首筆命中率由 33.3% 提升至 56.4%，並實際引導實驗室製程 [9]。
- **限制**：[8] 為綜述，無實驗；[9] 只有單一材料案例並依賴閉源模型。
- **設計啟示**：法規條文含大量金額、年限與專有名詞，本專題採「混合檢索 + 數值過濾」，並把門檻另外寫成規則檔（C4）。

### 2.1.4 購物 Agent 與商品實體比對

- **研究發現**：DeepShop 指出既有購物 Agent 基準過於簡單；在多屬性、篩選與排序需求下，RAG 因無法與網頁互動而表現不佳，網頁 Agent 也有明顯的篩選與排序錯誤 [5]。Peeters 等人顯示 LLM 零樣本商品實體比對在一半的資料集上勝過微調 PLM，但對 prompt 寫法高度敏感 [7]。
- **限制**：以國外電商為主，未涵蓋採購法規；比對結果不穩定。
- **設計啟示**：比價模組採兩段式比對（結構化規格欄位硬比對 + LLM 判斷），並要求至少 3 筆有效報價（C2）。

## 2.2 Domain Know-how

### 2.2.1 財產定義、最低使用年限與報廢

- **領域知識**：單價 1 萬元以上且使用年限 2 年以上為財產 [13][14]。最低使用年限是「正常使用下的最低年限」，到期仍可使用者應延後報廢；未到期而損壞無法修復者，得依程序專案報廢 [13][14]。報廢依損失金額分級核定，後續處分依《各機關奉准報廢財產之變賣及估價作業程序》[17]。
- **設計啟示**：以生命週期狀態機管理財產；報廢檢核同時看年限與狀態，系統不得對仍可正常使用的設備建議一般報廢。

### 2.2.2 採購金額門檻與流程

- **領域知識**：以國立臺灣大學請購作業規範為例，15 萬元以下為小額採購，經單位主管核准即可逕洽廠商；150 萬元以上為公告金額，請購時須附價格分析；另有查核金額與巨額採購門檻；共同供應契約則透過電子採購系統下訂 [15]。
- **設計啟示**：各校細節不同，門檻寫成可設定的 rules.yaml；另需偵測拆單規避門檻。

### 2.2.3 殘值與折舊

- **研究發現**：Huymajer 等人以真實重型機具交易資料比較多種迴歸方法，機器學習模型明顯優於傳統方法，但前處理與參數調整至關重要 [10]。Řezníček 與 Kropík 以二手平台掛牌資料估計，筆電每年約貶值 14.4%、手機約 28.2%，且 log-linear 模型較線性模型更貼近電子產品 [11]。2025 年科技業對 GPU 折舊年限的爭論（雲端業者採 6 年，批評者認為 2–3 年）說明「會計年限」與「經濟壽命」可能相差甚大 [16]。
- **限制**：殘值研究集中於重型機具、汽車與手機；實驗儀器缺乏交易資料。
- **設計啟示**：雙軌殘值——帳面價值走法定直線法，市場價值走 log-linear 或 GBM 並輸出區間；資料不足時標示低信心（C3）。

### 2.2.4 設備共享與使用率

- **領域知識**：監察院報告 [2] 與韓國 2026 年政策 [1] 皆指出，昂貴設備閒置的根源包括缺乏使用率追蹤、維護預算與人員，以及計畫結束後無退場機制。
- **設計啟示**：「借用登記 → 使用率分析 → 採購前查庫存」形成閉環；低使用率設備建議移撥或共享（C2）。
